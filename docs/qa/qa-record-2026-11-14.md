## Defects found

### Bug-1 (High / Critical): Deleting or replacing a referenced CV returns HTTP 500 and deletes the PDF file from storage

- Affected roles: `CANDIDATE` (cannot replace/delete CV) and `RECRUITER` (cannot download applicant CV afterward).
- Code location: `apps/api/src/modules/candidate/candidate.service.ts` (`uploadCv` lines 195-200 and `deleteCv` lines 235-238) vs `apps/api/prisma/schema.prisma` (`Application.resume` line 264 and `AiAssessment.resume` line 304 with `onDelete: Restrict`).
- Reproduction steps:
  1. Sign in as a candidate with an uploaded PDF CV (`POST /candidates/cv` -> `201`).
  2. Submit a job application (`POST /applications` -> `201`).
  3. Request `DELETE /candidates/cv` (or replace via UI `Replace`).
- Observed result:
  - `CandidateService.deleteCv` calls `await this.storage.delete(resume.storageKey)` before `await prisma.resume.delete({ where: { id: resume.id } })`.
  - Prisma throws `P2003` (`Foreign key constraint violated on the constraint: Application_resumeId_fkey`), returning HTTP `500` (`INTERNAL_ERROR`).
  - Meanwhile, the PDF file was already deleted from local storage, so subsequent `GET /candidates/cv` requests fail with HTTP `500` (`Error: File not found: <storageKey>`).
- Expected result: Either block deletion/replacement with an explicit domain error (`409` / `400`) before touching storage, or archive/detach old `Resume` records cleanly after preserving application/assessment references and delete storage only after DB mutation succeeds.
- Recommended follow-up: File as a dedicated `bug` Story in Jira (do not fix inside `SCRUM-89`).

### Bug-2 (Low / Medium UI): Global header renders hardcoded notification badge and non-functional bell button

- Affected roles: All (`CANDIDATE`, `RECRUITER`, `ADMIN`, anonymous).
- Code location: `apps/web/src/components/layout/site-header.tsx` lines 22-32.
- Observed result: Renders `<span ...>3</span>` and `aria-label="Thông báo tiến độ (3 mới)"` on a static `button` with no click handler or backend data, even when logged out.
- Expected result: Hide notifications for logged-out users or wire to real `Notification` records with working popover/read state.
- Recommended follow-up: File as a dedicated `bug` Story (or confirm whether a notifications ticket already exists in backlog).

### Bug-3 (Medium UI/Persistence): Company registration passes transient browser `blob:` URL as `logoUrl`

- Affected role: `RECRUITER`.
- Code location: `apps/web/src/app/company/register/page.tsx` lines 42 and 66.
- Observed result: Calls `URL.createObjectURL(file)` and saves the resulting `blob:...` URL to `logoUrl` without uploading the image file to API storage; image breaks after reload or in Admin moderation / public company pages. Also uses raw palette classes instead of semantic tokens (`globals.css`).
- Expected result: Upload logo through a backend asset endpoint (or omit invalid `blob:` URLs) and migrate component styling to semantic tokens.
- Recommended follow-up: File as a dedicated `bug` Story.
